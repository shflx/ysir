# 代码审查规范

- 审查顺序: 标准实现流程中，测试完成后才允许进入代码审查。

- 审查重点: 优先关注正确性、需求偏差、设计冲突、回归风险、可维护性、注释同步和测试缺口。

- 注释与可维护性: 检查关键模块、函数、类、属性、常量和复杂逻辑是否具备必要注释；若实现语义、边界条件、兼容性约束或隐含前提发生变化，必须确认相关注释已同步更新。

- 问题表达: 问题应包含等级、描述、定位和整改建议，避免只给笼统评价。

- 整改要求: 发现问题后应回到开发阶段完成整改；整改后重新执行必要验证与审查。

- 报告要求: 标准实现流程中，每轮代码审查都必须输出代码审查报告，并说明问题汇总和审查总结。
