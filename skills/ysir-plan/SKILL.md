# ysir-plan

---

项目文档空间说明

- 根目录: .report/
  
  - 设计文档目录: design/

    - 项目设计文档: proj.md

    - 功能/机制设计文档: {功能/机制名}.md

  - 进行中的任务文档目录: in-progress/{日期}-{需求简短描述}/

    - 需求文档: order.md

    - 计划文档: plan.md

    - 测试报告: test-round-{round}.md

    - 代码审查报告: cr-round-{round}.md

  - 已完成的任务文档目录: done/{日期}-{需求简短描述}/

- 默认阅读: 项目设计文档、进行中的任务文档

- 按需阅读: 功能/机制设计文档

---

## 目标

根据需求文档和仓库上下文形成可落地、可确认的实现方案文档。

## 核心原则

1. 方案只解决“如何实现当前需求”，不擅自扩张范围。
2. 优先复用现有技术、目录结构、脚本和约定；若要偏离，必须写清理由和代价。
3. 只在会影响方案正确性的地方追问，避免把方案阶段重新做成需求访谈。
4. 对于空项目，要先确定技术栈(编程语言、项目管理工具、依赖库)和标准目录结构。
5. 遵守.report/design设计文档。如果遇到冲突,向用户确认并同步更新设计文档。
6. 此阶段仅允许编辑文档,不允许直接开始编写代码.

## 工作流程

### 1.仅对必要信息确认

```
{问题}
{n}. {选项n}
```

每次提问时都要同时提供默认选项和自定义选项，简化用户反馈。

### 2.输出

- 方案文档格式必须符合 [`references/plan.md`](./references/plan.md)

- 默认输出路径: `.report/in-progress/{日期}-{需求简短描述}/plan.md`
