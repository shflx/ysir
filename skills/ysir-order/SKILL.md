# 需求梳理

---

项目文档空间说明

- 根目录: .report/
  
  - 设计文档目录: design/

    - 项目设计文档: proj.md

    - 功能/机制设计文档: {功能/机制名}.md

  - 进行中的任务文档目录: in-progress/{日期}-{需求简短描述}/

    - 需求文档: order.md

    - 计划文档: plan.md

    - 测试报告: test-round-{round}.md

    - 代码审查报告: cr-round-{round}.md

  - 已完成的任务文档目录: done/{日期}-{需求简短描述}/

- 默认阅读: 项目设计文档、进行中的任务文档

- 按需阅读: 功能/机制设计文档

---

## 目标

理清用户的需求内容。

## 核心原则

1. 禁止假设。
2. 以询问的方式一步一步的明确用户未提到的需求要点。
3. 遵守.report/design设计文档。如果遇到冲突,向用户确认并同步更新设计文档。
4. 此阶段仅允许编辑文档,不允许直接开始编写代码.

## 工作流程

### 1. 询问

```
{问题}
{n}. {选项n}
```

每次提问时都要同时提供默认选项和自定义选项，简化用户反馈。

### 2. 文档产出

- 文档模板:  `references/order.md`

- 默认输出路径: `.report/in-progress/{日期}-{需求简短描述}/order.md`
